# eRynok.Api

**eRynok.Api** — навчальний проєкт REST API для онлайн-маркетплейсу, який дозволяє продавцям розміщувати товари, покупцям оформлювати замовлення, а адміністраторам керувати користувачами та статусами замовлень.

## 1. Опис системи

Система призначена для організації взаємодії між продавцями та покупцями в межах онлайн-маркетплейсу.

API надає можливості для управління товарами, категоріями, користувачами та замовленнями. Дані зберігаються у JSON-файлах, що дозволяє працювати із системою без підключення окремої бази даних.

Проєкт розроблений з використанням ASP.NET Core Web API та побудований на основі розділення контролерів, сервісів, моделей і DTO.

## 2. Предметна область

Предметною областю проєкту є електронна комерція та організація продажу товарів через онлайн-платформу.

У системі передбачено три ролі користувачів:

- **Продавець (Seller)** — може розміщувати та керувати власними товарами.
- **Покупець (Buyer)** — може переглядати товари та створювати замовлення.
- **Адміністратор (Admin)** — призначений для управління системою та зміни статусів замовлень.

Основні об'єкти предметної області:

- **Користувач** — обліковий запис учасника маркетплейсу з визначеною роллю.
- **Профіль продавця** — додаткова інформація про продавця.
- **Профіль покупця** — додаткова інформація про покупця.
- **Категорія** — група, до якої належать товари.
- **Товар** — позиція, яку продавець розміщує на маркетплейсі.
- **Замовлення** — запис про придбання покупцем певного товару із зазначенням кількості, ціни та статусу.

Одне замовлення містить один товар. Під час створення замовлення система автоматично фіксує поточну ціну товару.

## 4. Основні сценарії використання

1. **Управління користувачами**
   - Створення облікових записів продавців, покупців та адміністраторів.
   - Перегляд списку користувачів.
   - Пошук користувачів за ім'ям або електронною поштою.
   - Фільтрація користувачів за роллю.
   - Редагування та видалення користувачів.

2. **Управління товарами**
   - Створення товарів продавцями.
   - Перегляд доступних товарів.
   - Пошук товарів за назвою та описом.
   - Фільтрація за категорією, продавцем і ціною.
   - Редагування та видалення товарів.

3. **Управління категоріями**
   - Створення категорій товарів.
   - Перегляд списку категорій.
   - Пошук категорій.
   - Редагування та видалення категорій.

4. **Управління замовленнями**
   - Створення замовлення покупцем.
   - Перегляд замовлень.
   - Фільтрація замовлень за покупцем, продавцем і статусом.
   - Перегляд окремого замовлення.
   - Зміна статусу замовлення.

## 5. Ресурси API

| Ресурс | Маршрут | Опис |
|---|---|---|
| Products | `/api/products` | Управління товарами |
| Categories | `/api/categories` | Управління категоріями |
| Users | `/api/users` | Управління користувачами |
| Orders | `/api/orders` | Управління замовленнями |

## 6. Реалізовані endpoints

### Products

| HTTP-метод | Endpoint | Опис |
|---|---|---|
| GET | `/api/products` | Отримання списку товарів |
| GET | `/api/products/{id}` | Отримання товару за ID |
| POST | `/api/products` | Створення товару |
| PUT | `/api/products/{id}` | Оновлення товару |
| DELETE | `/api/products/{id}` | Видалення товару |

Підтримувані параметри фільтрації: `search`, `categoryId`, `userId`, `minPrice`, `maxPrice`.

### Categories

| HTTP-метод | Endpoint | Опис |
|---|---|---|
| GET | `/api/categories` | Отримання списку категорій |
| GET | `/api/categories/{id}` | Отримання категорії за ID |
| POST | `/api/categories` | Створення категорії |
| PUT | `/api/categories/{id}` | Оновлення категорії |
| DELETE | `/api/categories/{id}` | Видалення категорії |

Підтримуваний параметр пошуку: `search`.

### Users

| HTTP-метод | Endpoint | Опис |
|---|---|---|
| GET | `/api/users` | Отримання списку користувачів |
| GET | `/api/users/{id}` | Отримання користувача за ID |
| POST | `/api/users` | Створення користувача |
| PUT | `/api/users/{id}` | Оновлення користувача |
| DELETE | `/api/users/{id}` | Видалення користувача |

Підтримувані параметри фільтрації: `search`, `role`.

### Orders

| HTTP-метод | Endpoint | Опис |
|---|---|---|
| GET | `/api/orders` | Отримання списку замовлень |
| GET | `/api/orders/{id}` | Отримання замовлення за ID |
| POST | `/api/orders` | Створення замовлення |
| PUT | `/api/orders/{id}/status` | Зміна статусу замовлення |

Підтримувані параметри фільтрації: `buyerId`, `sellerId`, `status`.

### Статуси замовлень

- `Pending` — очікує обробки.
- `Confirmed` — підтверджене.
- `Processing` — обробляється.
- `Shipped` — відправлене.
- `Delivered` — доставлене.
- `Cancelled` — скасоване.

## 8. Інструкція із запуску

### Вимоги

Перед запуском необхідно встановити:

- [ .NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
- Visual Studio 2022 або інше середовище розробки з підтримкою .NET 8.

### Клонування репозиторію

```bash
git clone https://github.com/USERNAME/eRynok.Api.git
```

Перейдіть до директорії проєкту:

```bash
cd eRynok.Api
```

### Відкриття проєкту

Відкрийте файл Solution у Visual Studio:

```text
eRynok.Api.sln
```

Дочекайтеся відновлення NuGet-пакетів.

### Запуск через термінал

Перейдіть до директорії, де розташований файл `.csproj`, та виконайте:

```bash
dotnet restore
dotnet build
dotnet run
```

Після запуску API буде доступне за адресою, зазначеною в консолі або у файлі `Properties/launchSettings.json`.

### Swagger

Для тестування API використовується Swagger UI. Після запуску відкрийте адресу Swagger, яку виведе застосунок, зазвичай:

```text
https://localhost:<port>/swagger
```

або

```text
http://localhost:<port>/swagger
```

### Збереження даних

Під час першого запуску застосунок автоматично створює необхідні JSON-файли в директорії `Data`, якщо вони відсутні.

Подальші зміни даних зберігаються у відповідних JSON-файлах.

## 9. Поточний стан проєкту

На першому етапі реалізовано основні CRUD-операції для товарів, категорій і користувачів, а також створення та перегляд замовлень і зміну їхніх статусів.

Система підтримує валідацію вхідних даних, перевірку зв'язків між сутностями, фільтрацію та обробку HTTP-помилок.

Авторизація та розмежування доступу за ролями наразі не реалізовані.
